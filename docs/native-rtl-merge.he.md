# מיזוג הפאטצ' עם תמיכת ה-RTL הנייטיבית של אנתרופיק

> מסמך תכנון — נכתב לאחר חקירה של ה-DOM החי וה-JS bundles של claude.ai (יולי 2026,
> Claude Desktop MSIX ‏1.22209.0.0). מטרתו: לקבוע לכל תחום מי מטפל — הנייטיב, הפאטצ',
> או שילוב — כך שהתוצאה תהיה הטובה ביותר בכל מקום, בלי ששני המנגנונים יילחמו זה בזה.

---

## 1. מה אנתרופיק שינו (ממצאי החקירה)

### 1.1 איפה זה רץ

אפליקציית הדסקטופ טוענת את **כל** תוכן הצ'אט/קוד מ-claude.ai (ב-`index.html` של ה-asar
כתוב במפורש: *"everything else gets loaded from claude.ai"*). לכן השינוי של אנתרופיק
חי בווב, מגיע לדסקטופ אוטומטית, ולא ניתן לדיפדוף כקובץ סטטי — רק דרך ה-DOM החי
או ה-bundles.

### 1.2 האלגוריתם שלהם (חולץ מה-bundle, chunk ‏`c06173196`)

שני רנדררים חדשים של markdown ("alluvium") מטמיעים `dir` בזמן רינדור:

- **`B_`** — הרנדרר של כרטיסיית ה-Code (סטרימינג עם word-fade, `data-alluvium`). **פעיל.**
- **`sP`** — רנדרר עם טיפוגרפיית `font-claude-response-body` — המחלקות של הצ'אט
  הרגיל. קיים ב-bundle אך **עדיין לא פעיל** בצ'אט (rollout הדרגתי / feature flag).
  כלומר: RTL נייטיב בצ'אט הרגיל כנראה בדרך.

הלוגיקה (שמות ממוזערים `fT`/`gT`/`uT`, יציבים רק בתוך אותו deployment):

```
dir = fT(gT(block))     // מוחל על: p, h1-h6, ul/ol, blockquote, עטיפת טבלה, footnoteDef
                        // לא מוחל על: fence (קוד), hr, math, תאי טבלה, li, הודעות משתמש

fT(text):               // first-strong פשוט על הטקסט
  לכל תו: RTL אם 0x0591-0x07FF / presentation forms / RLM,RLE,RLO
          LTR אם A-Z a-z / לטינית מורחבת (192-696) / יוונית-קירילית-ארמנית (880-1424)
  אחרת: undefined  → אין תכונת dir בכלל

gT(block):              // איזה טקסט נסרק — 80 התווים הראשונים בלבד
  paragraph  → שרשור השורות
  heading    → הטקסט
  list       → רק הילד הראשון של הפריט הראשון (!)
  blockquote → הילד הראשון
  table      → רק תא הכותרת הראשון (!)
  fence/hr/math → "" (אין dir)

uT (חילוץ טקסט): כולל inline code, kbd, math ו-fileUrl בטקסט הנסרק (!)
```

בנוסף: `unicode-bidi: isolate` גורף בכל הבלוקים, ותאי טבלה עם `text-align:left` קשיח.

### 1.3 מפת כיסוי — נייטיב מול המציאות

| משטח | RTL נייטיב? |
|---|---|
| כרטיסיית Code — בלוקי markdown של התשובות | ✅ `dir` per-block |
| כרטיסיית Code — תאי טבלה, li, בלוקי קוד | ❌ (בכוונה — אין dir) |
| כרטיסיית Code — **הודעות משתמש** | ❌ (`csDir:ltr`, בלי dir) |
| צ'אט רגיל — הכל (תשובות + הודעות משתמש) | ❌ (הרנדרר הישן; `sP` ממתין ב-bundle) |
| תיבות קלט (ProseMirror) — בכל מקום | ❌ (`ltr` + `unicode-bidi:isolate`) |
| כרום UI — sidebar, כותרות שיחות, דיאלוגים | ❌ |
| חלון Windows‏ (title bar וכו') בעברית | ❌ (הבאג הישן — הפאטצ' עדיין נחוץ) |

### 1.4 השוואת דיוק: הנייטיב מול הפאטצ'

| תרחיש | נייטיב | פאטצ' |
|---|---|---|
| פסקה עברית/אנגלית פשוטה | ✅ | ✅ |
| עברית שמתחילה בשם קובץ / inline code / URL | ❌ `ltr` | ✅ |
| עברית שמופיעה רק אחרי 80 תווים | ❌ | ✅ |
| פסקה מרובת-שורות מעורבת | ❌ dir יחיד | ✅ plaintext פר-שורה |
| רשימה עברית שפריטה הראשון אנגלי | ❌ | ✅ הצבעת רוב |
| טבלה עברית שכותרתה הראשונה אנגלית | ❌ | ✅ הצבעת רוב |
| תאי טבלה | ❌ | ✅ פר-תא |
| אריתמטיקה/LaTeX בפסקה עברית | ❌ | ✅ איי-בידוד |
| הודעות משתמש / קלט / UI | ❌ | ✅ |
| יציבות בסטרימינג (אפס הבהוב) | ✅ בזמן רינדור | ⚠️ תגובתי (50ms) |

מסקנה: הנייטיב הוא בערך "שכבה 1" של הפאטצ', עם יתרון יציבות בסטרימינג. המיזוג
לוקח את היציבות שלו במקרה הפשוט ואת הדיוק של הפאטצ' בכל השאר. פרט אחד אומץ
מהם חזרה: תווי הבקרה RLM/RLE/RLO/RLI נוספו ל-`RTL_RANGES` כ-RTL חזק.

### 1.5 למה הפאטצ' הנוכחי משתבש בכרטיסיית Code

1. **`resetDirOrPinLTR` מוחק `dir` נייטיבי.** פסקה אנגלית שאנתרופיק סימנו `dir="ltr"`:
   ‏`detectElDir` מחזיר null ‏(אין RTL) → הפונקציה מסירה את תכונת ה-dir. React מחזיר
   בסטרימינג → הפאטצ' מוחק שוב → מלחמה.
2. **`splitToDirectionalSpans` מוחק `dir` נייטיבי** מפסקאות מרובות-שורות.
3. **סטרימינג alluvium:** בלוקי frontier מרונדרים מחדש בתדירות גבוהה; כל ניתוח DOM של
   הפאטצ' (islands, החלפות text-node) בתוכם נדרס ומוחזר שוב ושוב — churn שנראה כשיבוש.
4. **CSS גורף:** הכלל `[dir]>*:not([dir])…{unicode-bidi:plaintext}` חל עכשיו גם על
   ילדי הבלוקים הנייטיביים (שבנויים אחרת — spans של word-fade) — אינטראקציה לא מתוכננת.

## 2. מטריצת המיזוג — תחום-תחום

**עיקרון הבעלות (חל על הכל):** כל `dir` שהפאטצ' קובע מסומן `data-rtl-managed="1"`.
תכונת `dir` בלי הסימון = נייטיב. את הנייטיב **לעולם לא מוחקים** ולא "מאפסים".

| # | תחום | נייטיב עושה | הפאטצ' עושה | מי עדיף | כלל המיזוג |
|---|---|---|---|---|---|
| 1 | כיוון בלוקים (p, h*, blockquote) | first-strong על 80 תווים, **כולל** inline-code/URL | ‏3 שכבות: בלי `<code>` → strip קידומות LTR ‏→ רוב-תווים | פאטצ' במקרי קצה; נייטיב מספיק ברוב המקרים | יש dir נייטיב ✛ הפאטצ' מסכים → לא נוגעים. אין dir נייטיב → פאטצ' כרגיל. נייטיב `ltr` אבל הזיהוי (כולל שכבת רוב-התווים) אומר `rtl` → דריסה מסומנת. בלוק נייטיבי מרובה-שורות מעורב → plaintext פר-שורה בלי לגעת ב-dir (מציל ציטוט עברי שנפתח בשורת סימון לטינית) |
| 2 | פסקאות מרובות-שורות מעורבות-שפה | dir יחיד לפי 80 הראשונים — שורות בשפה השנייה נשברות | `unicode-bidi:plaintext` פר-שורה | **פאטצ'** | מוסיפים plaintext ב-style **בלי להסיר** את ה-dir הנייטיבי (הוא נשאר בשביל יציבות React); ההסרה הקיימת נשארת רק ל-dir בבעלות הפאטצ' |
| 3 | רשימות (ul/ol/li) | dir על ul/ol לפי **הפריט הראשון בלבד**; ‏li בלי dir; padding פיזי | dir פר-li + היפוך padding + list-style-position | **שילוב** | ‏ul/ol: כמו כלל ‎#1. ‏li: אין נייטיב → הפאטצ' מטפל תמיד (תוספת טהורה). היפוך padding: רק כשה-padding בצד הלא-נכון בפועל |
| 4 | טבלאות — היפוך עמודות | dir על העטיפה לפי **תא כותרת ראשון בלבד** | הצבעת רוב על כותרות + עמודה ראשונה (`tableDirFromCells`) | **פאטצ'** (זיהוי) / נייטיב (מיקום) | עטיפה עם dir נייטיבי → ההיפוך כבר קרה, לא נוגעים. נייטיב פספס (כותרת ראשונה אנגלית, טבלה עברית) → הפאטצ' מסמן `dir` על ה-`<table>` עצמו (מסומן, לא על העטיפה שלהם) |
| 5 | טבלאות — תאים | כלום: יורשים rtl, ‏`text-align:left` קשיח — תא LTR מתערבב, מספרים נשברים | ‏`cellDir` פר-תא (מכיל-RTL, לא רק first-strong) | **פאטצ' חד-משמעית** — זה החיזוק המרכזי | הפאטצ' קובע `dir` מסומן לכל th/td לפי תוכנו + מיישר `text-align:start`. תוספת טהורה — לתאים אין dir נייטיבי. עובד גם בטבלאות נייטיביות וגם בצ'אט |
| 6 | LaTeX גולמי + אריתמטיקה ("2+3=5" מתהפך) | כלום (בצ'אט הדסקטופ אין רינדור LaTeX; אריתמטיקה בפסקה עברית משתקפת) | איי-בידוד `unicode-bidi:isolate` ‏(`segmentText`) | **פאטצ' — יכולת ייחודית** | נשאר בכל מקום. לא נוגע ב-dir אז אין קונפליקט. חריג יחיד: **דילוג על בלוקי frontier של alluvium** (סטרימינג פעיל) — מעבדים רק אחרי שהבלוק committed, כדי לא להילחם ברינדור החוזר |
| 7 | בלוקי קוד (pre/fence) | אין dir (בכוונה); אבל fence בתוך li של רשימת rtl יורש rtl בלי הגנה | `forceCodeLTR` + CSS מקבע ltr | **פאטצ'** (חגורת ביטחון) | נשאר כמו שהוא — הנייטיב לא שם dir על קוד אף פעם, אין התנגשות |
| 8 | הודעות משתמש (שני הטאבים) | **כלום** — גם בכרטיסיית Code | טיפול מלא | **פאטצ'** | נשאר במלואו |
| 9 | תיבות קלט | כלום (`ltr` קבוע) | זיהוי חי תוך הקלדה | **פאטצ'** (מאושר תקין) | נשאר במלואו, ללא שינוי |
| 10 | כרום UI ‏(sidebar, דיאלוגים, tooltips) | כלום | `processContainers` | **פאטצ'** | נשאר, עם גארד חדש: דילוג על אלמנטים בתוך תת-עץ עם dir נייטיבי |
| 11 | חלון Windows RTL ‏(main process) | לא קשור לשינוי | תיקון ה-titlebar | **פאטצ'** | נשאר ללא שינוי |
| 12 | CSS מוזרק | `isolate` גורף משלהם | גיליון כללים גורף | שילוב | ביקורת כלל-כלל: כללים שנוגעים ב-`[dir]` יוגבלו ל-`[dir][data-rtl-managed]` אלא אם הם מיטיבים גם עם הנייטיב (כמו `text-align:start` לתאים). הכלל `[dir]>*` הגורף — מוגבל לבעלות הפאטצ' |

## 3. שינויים קונקרטיים ב-`rtl-payload.js`

1. **`MANAGED_FLAG`** — קבוע חדש `data-rtl-managed`; ‏helper ‏`stampDir(el, dir)` שקובע
   dir + סימון, ו-`isNativeDir(el)` ‏(`hasAttribute('dir') && !hasAttribute(MANAGED_FLAG)`).
2. **`resetDirOrPinLTR`** — לא מסיר ולא משנה dir נייטיבי; פועל רק על אלמנטים בבעלות
   הפאטצ' או בלי dir.
3. **`splitToDirectionalSpans`** — מסיר dir רק אם הוא בבעלות הפאטצ'; נייטיב נשאר
   ומקבל plaintext בלבד.
4. **`processText`** — בראש הלולאה: `isNativeDir(el)` → מסלול "נייטיב": בדיקת
   disagreement (מלוא הזיהוי — שכבה 3 מבוססת רוב-תווים, לא "כל תו RTL") או
   plaintext פר-שורה לבלוקים מעורבי-שורות, ותו לא. אחרת המסלול הקיים, עם `stampDir`.
5. **`processTables`** — זיהוי "כבר הפוך נייטיבית" (העטיפה או הטבלה עם dir נייטיבי או
   computed rtl תורשתי) → דילוג על היפוך; **חדש:** לולאת תאים — `stampDir` פר th/td לפי
   `cellDir`, בכל טבלה (נייטיבית או לא).
6. **`processContainers`** — גארד: `el.closest('[dir]:not([data-rtl-managed])')` → דילוג.
7. **`isolateMath`** — גארד סטרימינג: דילוג על טקסט בתוך בלוק frontier של alluvium
   (זיהוי: ההורה תחת `[data-alluvium]` והבלוק עדיין מקבל mutations — או פשוט בדיקת
   קרבה ל-container הסטרימינג לפי היוריסטיקה שנקבע במימוש).
8. **CSS** — פיצול כללי `[dir]` לפי בעלות כמתואר בשורה 12 של המטריצה.
9. **MutationObserver** — אופטימיזציה: mutation שכולו בתוך תת-עץ נייטיבי עם הסכמה →
   no-op מוקדם (מוריד את ה-churn של הסטרימינג).

## 4. מה זה נותן

- **הכרטיסייה Code:** השיבושים נעלמים (אין יותר מחיקת dir נייטיבי ואין מלחמת סטרימינג),
  והפאטצ' עדיין משדרג שם: תאי טבלה, li מעורבים, אריתמטיקה, הודעות משתמש, תיבת קלט.
- **צ'אט רגיל:** מתפקד בדיוק כמו היום (הפאטצ' בבעלות מלאה).
- **עתיד:** כשאנתרופיק ידליקו את `sP` בצ'אט — הפאטצ' ייסוג שם אוטומטית לאותו מודל
  "נייטיב + השלמות" בלי צורך בעדכון.
- **בלי תלות בשמות ממוזערים:** כל הכללים מבוססי DOM (תכונת dir + סימון בעלות), לא על
  `fT`/`B_` וכו' שמתחלפים בכל deployment.
